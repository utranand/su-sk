# Invoice cancellation — reusable authoring contract

Playbook `database-correction.invoice-cancellation` **1.2.0** specializes the canonical [invoice incident playbook](../invoice-receipt-correction/README.md) with `operation: cancellation`. Read its [detailed procedure](../invoice-receipt-correction/prompts/task.md) and [SQL contracts](../invoice-receipt-correction/references/sql-contracts.md), plus both shared PBR/PAR rule files.

The SQL files in `templates/` are **authoring contracts, not executable fixes**. They deliberately contain AUTHORING_TEMPLATE_ONLY barriers. Generate a complete new five-script suite from the current incident's schema/data; independent review must reject any unresolved placeholder or worksheet marker. No prior case UUID/count/amount/authorization is a default.

This specialization accepts only `operation: cancellation`; route combined or mismatched work to the canonical incident playbook before proceeding. Follow the canonical stage dispatch: `prepare` authors, `dry-run`/`commit` reuse unchanged reviewed evidence, and `verify` performs read-only checks without regenerating or rebinding scripts/snapshots.

For cancellation, delete exact verified unpaid/unprinted invoices together with the corresponding exclusively linked unpaid charge transactions, exclusive QR/barcode rows and mappings. Invoice-only removal is incomplete while the charges remain collectible; verify exact charge-ID absence and the projected remaining IDs/amounts/balance. Never assign a guessed cancellation status or assume a cascade. Overdue does not imply paid; future due dates alone do not block. Preserve paid/shared/unrelated transactions, receipt/bank/manual accounting and future configuration; any conflicting payment or non-target dependency is a hard stop.

For an earlier invoice-only removal, derive exact original invoice/charge/reference ownership from immutable evidence, re-ground current transactions/dependencies/payments and obtain a new transaction-cleanup grant. Record already-absent invoice/QR/mapping counts as zero. Backup/restore only rows deleted by the current action, without recreating the earlier canceled invoices/QRs. Trace collection and actual cron/backfill/next-round behavior; changing a rate or rerunning cron does not replace a verified historical cancellation. No job/pointer/config change is implied.

Use [PROMPT.md](PROMPT.md) or supply `card`, with defaults `jira_env: su`, `database_env: smart_utilities_prod`, `stage: prepare`. Source templates do not execute automatically. Current exact-action approval, recoverable transaction and actual captured runtime evidence are mandatory for each later live dry-run, COMMIT or restore. Follow the canonical commit concurrency/quiet-window and uncertain-outcome rules. Reuse the parent workspace, register this playbook/version/stage, and publish exact ID/action lists and real results through footprints.

Validate and preview through the Sidekicks CLI; its `playbook run --dry-run` is a non-executing agent-step preview, not a database dry-run. See generated [RUN.md](RUN.md).
