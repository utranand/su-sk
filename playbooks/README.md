# Smart Utilities (`su-sk`) Incident Playbook Templates

This directory maintains standardized, operational playbook templates for production data corrections and incident resolution in the `su-sk` project.

Every playbook template and execution **MUST strictly follow all rules in the governing rule files cataloged in [PLAYBOOK_RULES.md](./PLAYBOOK_RULES.md)**:
- **Business Rules ([`rules/playbook-business-rules.md`](./rules/playbook-business-rules.md)):** Contains domain and business logic constraints including **PBR-01** (Invoice Lifecycle & Mutation Scope: Unpaid, Unprinted & Demographic Mutability), **PBR-02** (Billing Model Invariants: Accumulated vs Non-Accumulated Period Editability & Due Date Extension), **PBR-03** (Fiscal Year Cycle & Cross-Year Boundary Lock), **PBR-04** (Multi-Tenant Municipality Payer Disambiguation), **PBR-05** (Multi-Channel Satang Synchronization), and **PBR-06** (Invoice Deletion & Reconciliation Pre-Condition Guard).
- **Architect Rules ([`rules/playbook-architect-rules.md`](./rules/playbook-architect-rules.md)):** Contains architectural, security, execution, and reporting constraints including **PAR-01** (Zero DDL Floor / Least Privilege), **PAR-02** (Guarded Atomic Transactions), **PAR-03** (Mandatory Dry-Run / Rollback Default), **PAR-04** (Human Sign-Off Gate), **PAR-05** (Primary Key Specificity & Blast Radius), **PAR-06** (Zero-SQL Thai Executive Report), and **PAR-07** (Complete Workspace & Jira Audit Trail).

> **Contract:** Playbooks and executions declare references to rules **by files only** (`playbook_rules_file_ids`). Referencing a rules file mandates strict adherence to **all rule-ids declared within that file**.

## How to Add a New Playbook Template for a Different Issue Type

When introducing a playbook template for a new incident type:

1. **Scaffold Directory:**
   ```bash
   mkdir -p projects/su-sk/playbooks/database-correction-<new-issue-type>-template/templates
   ```
2. **Author `README.md`:**
   - Define `Issue Type ID` and `Match Criteria` (keywords, Thai terms, core intent).
   - Detail the 6 standard phases (Jira Verification, Workspace Setup, Readiness & Grounding, Practical SQL Generation, Footprint Registration, Human Sign-Off Gate).
   - Document any incident-specific quirks (e.g. meter rollover formulas, transaction matching).
3. **Add Templates in `templates/`:**
   - `01_investigate_readonly.sql.template`: Read queries verifying the problem without mutating state.
   - `02_backup.sql.template`: Read queries and JSON export payload for offline backup.
   - `03_correct.sql.template`: Guarded pure DML update ending in `ROLLBACK`.
   - `04_verify_readonly.sql.template`: Post-commit verification and blast-radius check.
   - `05_rollback.sql.template`: Pure DML rollback using hardcoded values.
   - `incident_report_th.md.template`: Executive incident report in Thai with prominent target UUID and bulleted TL;DR of database changes without SQL scripts.
4. **Register in Catalog:**
   - Add the new entry to the table above.
